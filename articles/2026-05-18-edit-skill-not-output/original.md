最近没日没夜的用 claude code 作为主要的平台做任何事情，得到一个非常重要的经验：要抑制住直接修改AI生成的产物的冲动，而要从skill/memory/claude.md等层面解决问题。比如最近我需要准备一些证据材料，就把微信聊天记录几年的信息录屏以后交给 Claude Code 帮我分析里面的对话内容，结果生成了一个详细的PDF格式的报告。这个时候如果我对这个最终的报告有任何不满，最习惯的方法当然是直接在PDF里面修改，删除几个字，加几句话，或者干脆把其中几页删掉。但是，一定一定要抑制住这个冲动，这种修改是没有前途的，一定要回到 Claude Cod，重新把需求说一遍，比如「不要前面的封面，报告尽量简洁」，它会做几件事情：1）把PDF改了 2）把你没有注意到的类似的问题也改了 3）把指令写入Skill文件以及Memory文件。这样当你还有别的修改的时候，可以在这个修改上叠加。否则的话，如果你直接改结果，你这边改完了，然后用Cloud Code再帮你改另外的东西，你前一个的改动就被覆盖掉了。除非你能保证，这个是你能做的最后一次改动。但这种情况基本上并不存在。所以，无论AI生成的是什么，是图片、是文章还是代码，一定要抑制住那种直接去改成品的冲动。现在去修改指令部分，看似多此一举，不顺手。时间也不见得最快，但这是正确的方法。
