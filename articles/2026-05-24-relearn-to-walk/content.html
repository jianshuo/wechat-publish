我最近核心的状态，是在一个新的世界里，要重新学会走路。


当你脚下的整个层次变了，原来的程序员，不见得在这个新层次里还会写程序；原来的创业者，不见得在这里面还会创业。这不是谦虚，是一个挺朴素的事实——地基换了，会盖房子这件事得重新学。


昨天深夜十二点多，我还在 X 上跟黄一孟聊天。他是心动、TapTap 的创始人，我们 2000 年就认识，是二十多年的老朋友了。他给我发来一句话，说：哎呦，我看了你的 GitHub 最近 commit 的时间，那个密度和强度，跟我最近很像啊。


我说，我们这种都是二十年前写程序的人，现在在 AI 里面，又重新开始学了。


不只是我们俩。最近这一段时间，尤其是上一波、上几波创业潮里的人，都在很努力地放低身段，认认真真地去写自己的第一个 skill，然后在这个新领域里发布一点东西出来。一群曾经写过很多代码、做过很大事情的人，现在像新手一样，从第一个小东西开始写起。


我得说清楚一件事。这个过程里，没有人有先天优势。我不认为我，不认为黄一孟，也不认为我周围任何一个老程序员，会比别人走得更快。二十年的经验在这件事上不一定加分，有时候反而是包袱——你越熟悉旧的那一套，越容易拿旧的尺子去量新的东西。


但这群人确实还有一个优势，而且我希望更多的人都能有这个优势——对新事物不抵抗。一个新潮流来了，先别急着评判，全身心跳进去，自己动手写起来。


至于怎么算「跳进去了」，我心里有个挺糙、但挺好用的标准：你每天自己手写、发给大语言模型的东西，如果还没到 1000 行，那真的，还没进入这个时代。这不是门槛，是个温度计——量的是你有没有真的把手伸进去。


为什么是 skill，为什么是现在？


我们花了很多力气，想搞清楚怎么让 AI 在自己的控制之下工作，这一路走了不少弯路。最早是 MCP，后来是命令行那一套，再往前还有 prompt 工程，前前后后大概走了两三年。到现在，是 Harness，是在 Harness 里用 skill 这种方式去驾驭上面那一层，再通过它去跟大语言模型工作。


大家都在试，各种各样的方法都在试。只不过现在看起来——每个人写自己的技能，技能再调用技能，以技能为中心，在上面长出一套有点像当年源代码那样的体系——这个东西已经日渐成型，很可能是未来十年的一个方向。


当然，这话没人说得准，也许再过两三个月，大家就觉得这是个坑，又去找更好的路了。但至少到现在，业界比较共识的，是把技能当成编程的核心阵地、当成大家的源代码，它似乎正在成为事实上的标准。


这让我想起互联网刚开始的时候。当年和 Web 并列的技术栈，多了去了，有十几个；瘦客户端还是胖客户端，争过很久。后来一条一条路都被打了叉，才慢慢收敛出 Web 这一条。今天我们说互联网就是网站、说应用就是 Web 应用，你甚至都叫不出那些落选者的名字了。


AI 大概也是同一个过程。只是这一次，我们这些二十年前写程序的人，又站回了起跑线，重新学走路。
