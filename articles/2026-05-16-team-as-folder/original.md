# 原始想法（从《AI 炼金术》对话里挑出来的一个点）

最近我刚搭了几个"团队"：
- 一个市场团队，每天早上 6 点干活
- 一个工程团队，每 4 小时醒一次干活
- 还在搭一个 PM 团队

这些"团队"是什么？说穿了——

每个"团队"，就是我目录里的一个文件夹（里面是一堆 .md），加上一个定时任务。

这件事拆开看，挺有意思：
- 代码 = "团队源代码" = prompt 文件夹（一堆 .md）
- 编译器 = 大语言模型
- 实例 = 跑起来的那个 agent = 你日常意义上的"团队"

我们过去说"团队"，脑子里默认是十几个人坐在工位上。现在团队的含义已经变了——团队 = 实例 = 跑起来的代码。

杠杆率很高——你写一次，它每天都在跑。你那些"很难"的工程任务，对它来说就一句话。

意味着：
- 组织设计变成文件系统设计
- 招人变成写 prompt
- 培训变成 git commit
- 一个人可以有一整个公司

但要警惕："你写好的"不等于"它真的跑得对"。还需要 PM 团队（也是个文件夹）做需求审核，需要客服团队（也是个文件夹）做对外，需要数据团队（也是个文件夹）做闭环。

未来五年最有杠杆的技能：会写"团队级别的 prompt"。
